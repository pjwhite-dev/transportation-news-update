## 2026-10-27: Editorial quality overhaul (owner request, 12 items)
- **Dates and articles**: every candidate's own page is fetched once (honest User-Agent) and dated from the page, in this order: JSON-LD, meta tags, a visible "Published:" line, a byline beside the headline, `<time datetime>`, the URL. An unlabeled `<time>` is used only when it is flagged as the publication time, sits inside `<article>`, or every `<time>` on the page agrees, because related-story widgets carry other dates (the Daily Star page proved it). No date means the item is dropped. Window: 48 h, 72 h over weekends and federal holidays (`config/editorial.yaml`). Government pages need 60 words, other pages 150. Consequence accepted: pages that block bots (HTTP 403) cannot be dated and are dropped; about 40% of raw candidates were already such pages or evergreen landing pages.
- **Summaries**: written by the local writer from the primary article text only, then deterministic grounding (numbers, names, modal verbs, titles/descriptors, filler), then gemma entailment, then one strict regeneration, then the article's own first sentences. Every failure is in the QA report.
- **Cross-edition repeats**: `data/published_groups.json` is derived from the last 7 archived editions. "Embeddings" are lexical (title tokens, unit figures) because no embedding model is installed and pulling one was not in the brief. Revisit if repeats slip through.
- **Docket**: status comes only from the latest Federal Register document's type and action (API). OIRA review status comes from reginfo.gov's public "rules under review" XML. reginfo's EO 12866 meeting search answers automated requests with HTTP 403, so it is NOT scraped; upcoming meetings are listed per rule in `tracker/rulemakings.yaml` (`oira_meetings`), seeded from the owner (2120-AL82: Oct. 29, 2026). FCC SB Docket 25-306 is tracked by docket number. A daily FR search adds new rulemakings to `tracker/discovered.yaml` automatically.
- **Old status wording removed**: "Comment period closed; pending final rule" and "Open for comment" asserted things the record did not say (the FMCSA ADS error). Tests that pinned the old wording were rewritten to the new rule.
- **Market label** comes from the quotes' own timestamps and the NYSE holiday calendar.
- **No gate was weakened.** The docket gate now also requires the FCC docket.

Choices I made carrying those out:
- **Agency site searches replace the three dead feeds in the edition too** (`web_discovery.OFFICIAL_SITE_SEARCHES`, `news_engine.fetch_official_site_search`), since the edition had the same failures. They go through Google News RSS (the endpoint already in use), section "Federal Actions", origin "Official site search", source renamed to the agency. Titles under five words are dropped: `site:faa.gov` also returns tool pages ("tfrweb", "ATCSCC Advisory", "Search Results"); everything else still faces the normal reading rules. NASA and DoD keep their feeds. Live wire: every 10 minutes each, inside the one-Google-query-per-30-s limit.
- **Lead bar:** it was only on the mockup board; the real page never showed it. The page keeps the lead story and the Developing list; the bar stays in the code that picks the lead.
- **"Desks" become "categories"** on the page; the seven groupings are unchanged. Toggles are remembered per reader (browser storage); "Show all" appears when any is off. The 24-hour pulse sidebar is gone (counts are on the toggles); the rulemaking docket is a collapsed row above the feed.
- **Labels:** "Quick summary" (code matched every name, number and date in our summary to the article) and "Summary double-checked" (a second model confirmed each sentence matches the article); the footer says neither checks the reporting itself. The feed's public `check` values are `quick` / `checked`; internal status names are unchanged. A test fails if "verif" appears in the page files.
- **Market strip:** the edition's Finnhub watchlist (same key, same endpoint), refreshed every 5 minutes while NYSE is open and once after each close, written to `.runtime/live_site/market.json`; the edition's `data/market.json` stands in when that is missing. Hidden when no snapshot is fresh. Placed as a thin band under the lead, labelled with the quotes' own session date (and the time when intraday).
- **Sweep line:** one source at a time, 8 seconds each, with a fade (no fade for reduced motion). Google queries show as `Google News: “query”`.
- **Deny list checked again after a Google link resolves.** The first real model run put two Mordor Intelligence "Market Size, Share & 2032 Growth Trends Report" pages on the page: they arrived as news.google.com links, so the host check on the wire never saw the publisher. The desk now checks the resolved URL, and drops market-research titles ("market size", "CAGR", "growth trends report", "market report", "forecast to 20xx") before any model. The stories already in the store that matched were dropped by hand (3 shown, 9 waiting).
- **A writer outage never costs a story.** The first real run dropped 54 stories (one a real FCC rule story) as "writer unavailable": the fallback model was configured as `qwen3.6:27b` but is installed as `qwen3.6:27b-q4_K_M`, and an unreachable model counted as one of the story's two attempts. Now a model failure leaves the story queued with no attempt counted; if the writer stays down, the doctor's HEADLINES level shows it as headline and link. The service checks at start that every configured model is installed. The affected stories (and those shown headline-only while the writer was down) were put back in the queue by hand.
- **Model timeouts cover a model load.** Writer and checker do not fit on the 24 GB card together, so each switch reloads one; the 30-second stall limit failed calls during the load. Stall limit now 120 s; budgets first pass 150 s, check 300 s, score 240 s; the doctor's silence limit 600 s.
- **Category filing.** The edition's `infer_section` ends in "UAS / Drones" for anything it does not recognize, which labelled freight-rail and train-theft stories as drone news. The triage call (already made for every story) now also returns the category, constrained to the seven keys; before that, code files a "UAS / Drones" story with no drone words by rail words, else in the last category.

## 2026-10-30 (afternoon): owner's second review of the live page
- **A story must score at least 50 to lead, even when there is no lead.** The first real run made a profile of a Malaysian air-taxi engineer (score 15) the lead because "no current lead" let any checked story in. The bar's floor (50) is now also the minimum for any lead, including the 30-hour takeover; when the lead goes stale and nothing qualifies, the lead is cleared and the page says no story has been significant enough to lead. The Developing list beside it needs 40. Minor stories stay in the feed. The bad lead was cleared by hand.
- **Docket** moved into the lead area's side column under Developing: four items, the rest behind "N more on the docket".
- **Markets** became a second ticker, moving like the wire and stuck under it at the top of the screen (dark band, green/red changes); the session label rides along as the first item.
- **Tagline under the title** (config `site.tagline`): "Updates itself around the clock. New stories appear within minutes, each summarized by AI and linked to its source."
- Google queries on the sweep line show their first phrase ("Google News: unmanned aircraft system") instead of the raw query.
- Checked without the GPU (owner stopped GPU use for the newsroom at 12:40 UTC): feed rendered from the store with `live_service.py render` and served as static files.
- **Stories with only a date show when we found them, not noon.** Pages that give just a date are stamped noon Eastern by the shared date reader (kept, the edition depends on it). On the live page such a story is never dated later than we found it, keeps a feed's real time from the same day, and shows "found 8:29 a.m." in place of a clock time ("no time given" if it is from an earlier day).
- **Public delivery through GitHub only.** news.peterjwhite.org's DNS is on Google Cloud DNS, not Cloudflare, and
  the brief names GitHub Pages; so the page is served by Pages at /live/ and its feed is a file on the `live-feed`
  branch read from raw.githubusercontent.com (CORS open, cached up to 5 minutes). No new service or account. Each
  push is an ordinary commit (no force, per AGENTS.md), at most every 3 minutes plus a 10-minute heartbeat, so the
  branch grows by roughly 150-250 small commits a day; if that ever matters, the branch can be replaced with the
  owner's approval.
- **Headline override login = GitHub sign-in** (owner's choice of three). The /login page holds no secret and
  changes nothing itself; it opens a pre-filled issue. Only issues opened by the repository owner, less than
  6 hours old, are applied; others are ignored without a reply. Requests are visible on the public repository.
- **Market additions are live-only** (`market.extra` in config/live.yaml) so the morning edition's market section
  does not change.
- **Live page at the root, edition at /edition/** (owner: "make the live page at news.peterjwhite.org"). The edition keeps its archive and search; the live page footer links "Morning edition" and "Archive". The email newsletter is untouched; any link in it to the bare domain now opens the live page, one click from the edition.
- **Site domain is advancedtransportation.live** (owner's choice of "move everything"). Repository Pages domain switched by API with the stored token; HTTPS enforced once GitHub issued the certificate. news.peterjwhite.org is left to the owner to forward; nothing in code depends on it.
- **Impact shown as a word, never the number** (owner chose the word badge). Routine (<30), Notable (30-49), Major (50+, the score a story needs to lead), Landmark (75+, rare). Only scored stories (summary double-checked) carry one; the hover text and footer say it is an AI estimate of impact, not a judgment of the reporting. The rulemaking docket was removed from the live page (owner); the edition keeps its tracker.
