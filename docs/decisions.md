## 2026-10-27: Editorial quality overhaul (owner request, 12 items)
- **Dates and articles**: every candidate's own page is fetched once (honest User-Agent) and dated from the page, in this order: JSON-LD, meta tags, a visible "Published:" line, a byline beside the headline, `<time datetime>`, the URL. An unlabeled `<time>` is used only when it is flagged as the publication time, sits inside `<article>`, or every `<time>` on the page agrees, because related-story widgets carry other dates (the Daily Star page proved it). No date means the item is dropped. Window: 48 h, 72 h over weekends and federal holidays (`config/editorial.yaml`). Government pages need 60 words, other pages 150. Consequence accepted: pages that block bots (HTTP 403) cannot be dated and are dropped; about 40% of raw candidates were already such pages or evergreen landing pages.
- **Summaries**: written by the local writer from the primary article text only, then deterministic grounding (numbers, names, modal verbs, titles/descriptors, filler), then gemma entailment, then one strict regeneration, then the article's own first sentences. Every failure is in the QA report.
- **Cross-edition repeats**: `data/published_groups.json` is derived from the last 7 archived editions. "Embeddings" are lexical (title tokens, unit figures) because no embedding model is installed and pulling one was not in the brief. Revisit if repeats slip through.
- **Docket**: status comes only from the latest Federal Register document's type and action (API). OIRA review status comes from reginfo.gov's public "rules under review" XML. reginfo's EO 12866 meeting search answers automated requests with HTTP 403, so it is NOT scraped; upcoming meetings are listed per rule in `tracker/rulemakings.yaml` (`oira_meetings`), seeded from the owner (2120-AL82: Oct. 29, 2026). FCC SB Docket 25-306 is tracked by docket number. A daily FR search adds new rulemakings to `tracker/discovered.yaml` automatically.
- **Old status wording removed**: "Comment period closed; pending final rule" and "Open for comment" asserted things the record did not say (the FMCSA ADS error). Tests that pinned the old wording were rewritten to the new rule.
- **Market label** comes from the quotes' own timestamps and the NYSE holiday calendar.
- **No gate was weakened.** The docket gate now also requires the FCC docket.

## 2026-10-28: orchestration scripts get logic in Python
Anything in a `.ps1` file that has a right answer (git hygiene, file selection) belongs in a tested Python module the script calls; PowerShell 5.1 turns native-command stderr into terminating errors under `$ErrorActionPreference = "Stop"`, and a script change cannot be exercised by the Python tests.

## 2026-10-28: CI link failures are cured by denying the host, not by relaxing the CI gate
The Pages workflow re-checks every link of the saved edition from GitHub's network. finance.biggo.com refuses that network, so the re-check failed and the site never deployed (three failure e-mails). I did NOT make the CI check tolerant of unreachable links: that would weaken a gate. Instead: (1) the workflow echoes gate failures as annotations; (2) BigGo and Pluang (retail finance aggregators, rule 8) are in `deny_hosts`; (3) the doctor reads those annotations on a `deploy_unverified` failure, adds any host the CI could not reach (HTTP None/5xx) to `deny_hosts`, pushes, and rebuilds the edition once. Open question for the owner: whether the CI re-check should keep doing live link checks at all, since the publishing machine has already verified them minutes earlier.
